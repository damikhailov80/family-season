# Семейный сезон

Постер следующего месяца вашей семьи — что ждёт вас и близких: название сезона, четыре
недели с местом под фото, личные проекты каждого и хроника настроений.

Метафора зашита в название: месяц — это сезон, недели — серии, личные проекты — сюжетные
линии, итоги — финал, а идеи на следующий месяц — анонс. Замысел простой: соберите постер
заранее, распечатайте на двух листах A4, повесьте на холодильник и проживите месяц.

На `/` — лендинг с объяснением и тремя готовыми примерами: «Месяц Человека-паука» на четверых,
«Месяц настолок» на троих и «Месяц первых раз» на пятерых — сезоны нарочно разной
прожитости, от только начавшегося до законченного, и каждый в своей теме оформления
и со своими рисунками. Любой можно **форкнуть** и переписать
под свою семью, либо собрать сезон с нуля. Готовый сезон живёт строкой в вашем кабинете
и открывается по короткому постоянному адресу: его можно показать по личной ссылке или
выложить на витрину сообщества.

Страницы сайта:

Сайт говорит на трёх языках — русском, английском и польском, — и язык стоит первым
сегментом адреса: `/ru`, `/en`, `/pl`. Его можно поменять руками в адресе, ссылками в
подвале или настройкой в кабинете; у сезона язык свой, он выбирается при заведении и
подписывает сам лист.

| Адрес | Что |
| --- | --- |
| `/<lang>` | Лендинг: как собрать сезон и что на постере |
| `/<lang>/sheet`, `…/sheet/edit` | Черновик невошедшего: живёт в его же браузере |
| `/<lang>/season/<code>` | Свой сезон из базы; `…/edit` — он же в правке |
| `/<lang>/s/<code>` | Выложенный сезон, в том числе наши примеры |
| `/<lang>/p/<token>` | Свой сезон по личной ссылке: просмотр и форк |
| `/<lang>/seasons` | «Мои сезоны»: свои, избранное и опубликованные — только для вошедших |
| `/<lang>/ideas` | «Идеи сообщества» — витрина выложенных сезонов своего языка |
| `/<lang>/account` | Кабинет: язык, состав семьи для новых постеров, выход |
| `/<lang>/privacy` | Политика приватности — её адрес требует Google |
| `/api/auth/*` | Вход через Google (Auth.js) |

Next.js (App Router, бандлер Turbopack) + TypeScript, стили — CSS Modules; в браузер едет
ровно одна сторонняя библиотека — счётчик Google Analytics, и только у того, кто разрешил
его баннером согласия. Всё остальное живёт на сервере: Auth.js в браузер не едет, кнопки
входа это `<form>` с серверным действием. Сам постер целиком клиентский.

| Когда | Что | Сколько |
| --- | --- | --- |
| `git commit` | `prettier` и `oxlint` по тому, что коммитится | доли секунды |

Разово пропустить хук — `git push --no-verify`. Тестам нужна поднятая база и строка
`E2E_DATABASE_URL` в `.env.local` — см. «Тесты».

## Тесты

E2E на Playwright. Заголовок теста — утверждение о том, как продукт должен себя вести,
поэтому тесты заодно служат описанием сценариев: что гарантировано, видно из `e2e/`.

Тестам нужна **отдельная** база: перед каждым прогоном её схема сносится и собирается
заново из миграций и посева примеров. Заводится она рядом с дев-базой:

```bash
docker exec family-season-db createdb -U postgres family_season_e2e
# и строка в .env.local, см. .env.example:
# E2E_DATABASE_URL=postgres://postgres:local@localhost:5432/family_season_e2e
```

```bash
npm run e2e       # слепок + сборка + тесты — полный прогон
npm run e2e:only  # только тесты, по уже собранному: когда правишь сами спеки
npm run e2e:db    # только привести тестовую базу к слепку
npx playwright show-report
```

`e2e` пересобирает проект намеренно: `e2e:only` гоняет тесты по **прошлой** сборке, и
поправив код приложения, вы молча проверили бы старое. Быстрый он только для правки самих
спеков.

Тесты идут против `next start` на порту 3100, а не против дев-сервера: дев смотрит в
рабочую базу, да и второй `next dev` в одном проекте не поднять. Сборка занимает секунд
десять. Скрипт слепка откажется работать, если `E2E_DATABASE_URL` совпала с `DATABASE_URL`, —
он сносит схему целиком, и промахнуться базой тут стоит слишком дорого.

## Хуки

Ставятся сами при `npm install` (husky):

| Хук | Что делает |
| --- | --- |
| `pre-commit` | `prettier` и `oxlint` по тому, что коммитится |
| `pre-push` | `npm run lint`, `npm run typecheck` |

**E2E в `pre-push` пока нет, и это решение, а не пробел.** Набор из одного теста не стоит
ожидания, а хук, который тормозит без пользы, начинают обходить `--no-verify` — и дальше
обходят уже по привычке. Когда сценариев наберётся достаточно, в `.husky/pre-push`
добавляется строка `npm run e2e`: она сама приводит базу к слепку и собирает проект.

Не проходит по делу — чините. Не проходит некстати — `git push --no-verify`. Хук, который
нельзя обойти, однажды заставит обходить себя правкой самого хука.

Форматирование — Prettier с настройками под сложившийся стиль (без точек с запятой,
одинарные кавычки, ширина 100). Собираемые файлы и `*.md` в `.prettierignore`: первые
разошлись бы со сборкой, вторые свёрстаны по ширине руками.

## Вход

Вход через Google на Auth.js. Хранилища у него нет: сессия лежит в зашифрованной куке,
на сервере о пользователе не остаётся ни строчки. «Мои сезоны» открываются только вошедшим.

Чтобы вход заработал локально, нужны три переменные — образец в `.env.example`,
значения кладутся в `.env.local` (он не попадает в git):

```bash
npx auth secret            # запишет AUTH_SECRET в .env.local
```

`AUTH_GOOGLE_ID` и `AUTH_GOOGLE_SECRET` берутся из OAuth-клиента в Google Cloud Console
(тип Web application). Разрешённые redirect URI:

```
http://localhost:3000/api/auth/callback/google
https://<домен>/api/auth/callback/google
```

Проверка, что серверная часть поднялась:

```bash
curl http://localhost:3000/api/auth/providers
# {"google":{"id":"google","name":"Google","type":"oidc",…}}
```

## Хранилище

Сезон живёт **строкой в базе**, а в адресе стоит только короткий код этой строки
(шесть знаков, перестановка битов её id). Таблиц шесть плюс настройки аккаунта:

| Таблица | Что в ней |
| --- | --- |
| `user_settings` | Состав семьи для новых постеров |
| `user_seasons` | Свои сезоны: содержимое бланка, имена отдельно, тема, рисунки, Поделиться ссылкой |
| `public_seasons` | Выложенные сезоны — **копии**, со своим постоянным адресом |
| `public_likes`, `public_favorites`, `public_forks` | Что публикация собрала у людей |
| `public_reports` | Жалобы: текст, кто пожаловался и на кого (автор публикации) |

Содержимое хранится разобранным — тем же позиционным массивом, в котором бланк всегда и
жил (`src/model/codec.ts`), только в `jsonb`. Имена членов семьи лежат **отдельно** от
него: по содержимому считается уникальность публикации (одинаковых на витрине не бывает),
а имена в это сравнение не входят — их же можно заменить случайными при публикации.

У невошедшего сезона в базе нет вовсе: его черновик лежит в `localStorage` браузера,
один на браузер. У каждого аккаунта не больше ста сезонов, ста закладок и ста публикаций.

```bash
# строка подключения — в .env.local, см. .env.example
npm run db:status        # что накатано, что осталось
npm run db:migrate       # шаги из tools/db/migrations, по одному в транзакции
npm run db:seed          # кладёт наши примеры в public_seasons как системные сезоны
npm run db:reports       # очередь жалоб; -- --block <code> «почему» закрывает публикацию
```

Витрина не прячет сезоны по жалобам сама: порог — повод посмотреть, а решение принимает
человек. Закрытая публикация (`blocked_at`) остаётся в базе, но не показывается нигде —
ни в «Идеях», ни по прямой ссылке; выложить такой же контент заново нельзя. Публикацию,
на которую пожаловались, автор снять с витрины может, а удалить — нет: жалоба должна
указывать на то, на что подана.

Локально проще всего поднять базу в докере:

```bash
docker run -d --name family-season-db \
  -e POSTGRES_PASSWORD=local -e POSTGRES_DB=family_season \
  -p 5432:5432 -v family-season-pgdata:/var/lib/postgresql \
  postgres:18-alpine

# DATABASE_URL=postgres://postgres:local@localhost:5432/family_season
```

Том монтируется в `/var/lib/postgresql`, а **не** в `/var/lib/postgresql/data`: с 18-й версии
образ хранит данные в подкаталоге с номером версии, и старый путь он отвергает с ошибкой.
Снести всё вместе с данными — `docker rm -f family-season-db && docker volume rm family-season-pgdata`.

В проде подойдёт любой PostgreSQL — например Neon или Vercel Postgres. **Без базы сайт
работает**: лендинг, примеры, постер, печать и вход от неё не зависят. В кабинете при
этом на месте состава семьи и списка сезонов пусто, а внизу — тост «не удалось
загрузить»: показывать вместо настоящих данных умолчание значило бы врать. Ни имени,
ни почты в базе нет — строки именуются непрозрачным ключом аккаунта.

Проверить, как выглядит отвалившаяся база, проще всего так — остановить контейнер и
открыть `/account`:

```bash
docker stop family-season-db     # в кабинете пусто и тост, остальной сайт работает
docker start family-season-db
```

В логах сервера при этом будет строка `[db] запрос не прошёл (settings:read:account,
код ECONNREFUSED)` с кодом Postgres и причиной — наружу она не выходит намеренно.

## Деплой

Vercel определяет Next.js сам: подключить репозиторий, собрать без дополнительных настроек.
Переменные `AUTH_*` и `DATABASE_URL` заводятся в настройках проекта; `AUTH_URL` не нужен —
адрес Vercel подставляет сам. Переменные подхватываются новым билдом: заведёте после
деплоя — нужно пересобрать.

`GA_ID` — идентификатор потока Google Analytics, и он же рубильник всего разговора о
согласии: пусто — нет ни счётчика, ни баннера, ни ссылки «Куки» в подвале, ни раздела в
кабинете. Переменная серверная намеренно (не `NEXT_PUBLIC_`): публичная подставляется
сборкой, и выключить счётчик без пересборки стало бы нельзя.

**Схему на прод накатывают руками — сама она не появится.** Ни один шаг сборки миграцию
не зовёт (её падение завалило бы деплой сайта, который работает и без базы):

```bash
vercel env pull --environment=production .env.production.local
node --env-file=.env.production.local tools/db/migrate.mjs
node --env-file=.env.production.local --import tsx tools/db/seed-examples.ts
```

Посев идёт после схемы и кладёт девять системных сезонов — три примера на каждом языке.

Зовём скрипты напрямую, а не `npm run db:migrate` и `npm run db:seed`: те подмешивают
`.env.local`, и накатить на дев вместо прода слишком легко. `--env-file` — флаг **node**,
а не приставка к команде: `--env-file=… npm run db:seed` оболочка просто не поймёт, а если
и поймёт, npm-скрипт всё равно возьмёт свой `.env.local`.

Перед подключением каждый из них печатает хост и имя базы — это и есть проверка, что едем
куда надо.

В `next.config.ts` не стоит включать `output: 'export'`: статический экспорт выключает
роут-хендлеры, а серверная часть в планах.

## Два слоя: бланк и заполнение

| | Шаблон (бланк) | Заполнение |
| --- | --- | --- |
| Что это | Всё, что печатается: заголовки, тема месяца, недели, состав семьи, проекты и цели | Настроения по дням, прогресс проектов, записи в «Итогах месяца» и «Идеях на следующий месяц», фото |
| Где живёт | В строке сезона (или в черновике браузера) | В локальном JSON (`src/data/examples/<id>.json`) |
| Копируется при форке | да | нет |
| Печатается | да | нет |

Печать всегда даёт **пустой бланк**: шкалы прогресса пустые, клетки настроений пустые, поля для записи
(«Итоги месяца», «Идеи на следующий месяц») пустые, в полароид-рамке пустое место под вклейку бумажного фото. Заполняется всё руками
уже на бумаге. Заполнение существует только для примеров — чтобы показать, как выглядит
прожитый месяц. Какой набор показать, говорит колонка `fill_id` у системного сезона —
наши примеры лежат на витрине такими же строками, как людские, только без автора.

## Печать: ровно две страницы A4

Лист рассчитан на две страницы, по две нумерованные секции на каждой:

| Страница | Что на ней |
| --- | --- |
| 1 | Шапка, «1. Тема месяца», «2. Недели месяца», «Наша цель на месяц» |
| 2 | «3. Личные проекты», «4. Настроение нашей семьи», «Идеи на следующий месяц» |

Свободное место на каждой странице уходит внутрь одного блока — поля для записи от руки:
на первой это рамка «Итоги месяца» внутри темы месяца, на второй — «Идеи на следующий
месяц». Остальные блоки сохраняют веб-пропорции. Раскладка проверена на худшем случае — пять человек и месяц из
31 дня — и всё равно укладывается в два листа. В диалоге печати оставьте поля по умолчанию: разметка
рассчитана на поля 10 мм (`@page` в `src/styles/print.css`).

## Как пользоваться

1. Чистый постер — **Новый сезон** в шапке сайта. Сперва спросят название (подставлено
   умолчание — месяц и тема), а дальше: вошли — сезон заводится в кабинете, с составом
   семьи из настроек; не вошли — тот же бланк ложится черновиком в браузер.
2. Из примера — карточка на главной ведёт на выложенный сезон, дальше **Форкнуть**:
   копия ляжет вам в «Мои сезоны» (а невошедшему — черновиком в браузер) вместе с той
   темой и теми рисунками, что сейчас на экране.
3. Править текст прямо на постере: клик по любому подчёркнутому месту. Кнопки темы и
   рисунков плавают в правом нижнем углу и работают везде — постер перекрашивается
   целиком, тема за темой, а рисунки меняются набор за набором.
4. **Ничего сохранять не надо.** Свой сезон пишется в базу сам, черновик — в браузер.
   У черновика в панели есть одна кнопка про это: вошедшему «Сохранить в мои сезоны»
   (одно нажатие — и черновик стал сезоном), остальным «Войти и сохранить» — вход
   возвращает в кабинет и черновик там уже строкой.
5. **Показать сезон** можно двумя способами. Иконка со звеном цепи выдаёт **личную
   ссылку**: по ней постер откроется у кого угодно без входа, править он не сможет, а
   ссылку можно отозвать или заменить новой. Мегафон **выкладывает копию на витрину**
   «Идеи сообщества» — там её увидят все; при публикации можно заменить имена семьи на
   случайные.
6. **Форкнуть** есть и у своего сезона: следующий месяц удобно собирать из прошлого,
   а прошлый при этом остаётся.
7. На чужом выложенном сезоне слева стоят **звёздочка** (отложить себе), **сердце**
   (лайк) и **флажок** (пожаловаться — с комментарием, он уходит нам, а не автору).
8. **Печать** — принтер в правом углу панели; в диалоге печати выбрать «Сохранить в PDF».
9. Повесить распечатку на холодильник и прожить сезон, отмечая всё от руки.

Звёздочка, лайк и жалоба требуют входа: нажмёте не войдя — постер предложит это сделать
и вернёт вас ровно туда, где вы были.

В «Моих сезонах» три списка: свои сезоны, отложенное чужое и свои публикации со
статистикой («в избранном у N», «форкнули N»). Свои строки можно переименовать
(карандаш) или удалить (крестик); имя нужно только списку — на постере оно нигде не
печатается. Убрать публикацию с витрины можно оттуда же: если её никто не отложил себе,
она исчезнет совсем, а если отложил — останется открываться по прямой ссылке.

Черновик невошедшего живёт **только в его браузере** и только один — но видно его там же,
в «Моих сезонах»: строкой с названием, месяцем и датой, которую можно открыть,
переименовать или удалить. Раз он один, форк и новый сезон затирают прежний, и окно об
этом предупреждает заранее, называя, что именно исчезнет. Оно же предлагает войти — тогда
прежний черновик уедет в коллекцию первой строкой, а не пропадёт.

Режим виден в адресе: `/season/<code>` — просмотр, `/season/<code>/edit` — правка. Оба
адреса можно сохранить в закладки, переслать себе и открыть в новой вкладке. Кнопки
«назад» и «вперёд» работают как на обычном сайте — терять при этом нечего, содержимое
лежит не в странице.

## Что редактируется, а что нет

Редактируется (и хранится в самом сезоне):

- заголовок листа и лента-девиз;
- месяц (стрелки ‹ ›), подзаголовок темы, вопрос в блоке «Итоги месяца»;
- подписи-заметки секций, названия и тексты четырёх недель;
- общая цель месяца;
- состав семьи: от 2 до 5 человек — имя, рисунок (папа / мама / сын / дочь, меняется кликом
  по аватару), название проекта, описание, личная цель;
- тема оформления — **сто наборов** из подборки Canva «100 цветовых сочетаний»
  («Пустыня», «Морская волна», «Кухня 1950-х»…). Плавающая кнопка в правом нижнем углу
  бросает постер в случайную другую тему, а название текущей видно прямо на ней. Выбранная
  тема хранится рядом с сезоном (в бланк она не входит), переживает форк и печатается.
  На чужом выложенном сезоне она примеряется и уезжает в адрес пометкой `?p=` — чтобы
  можно было прислать ссылку на увиденное, не трогая чужую строку. Тему задают четыре краски набора — ими красятся плашки, рамки,
  чернила и герои, никаких других цветов на постере нет. Тема красит только постер: сайт
  вокруг него нейтрально-графитовый и не меняется никогда;
- рисунки постера — **двадцать наборов** по восемь рисунков («Классика», «Зима»,
  «Путешествие», «Питомцы»…). Вторая плавающая кнопка бросает постер в случайный
  другой набор, а три рисунка текущего видно прямо на ней. Набор устроен ровно как тема:
  хранится рядом с сезоном, примеряется на чужом пометкой `?i=`, переживает форк и
  печатается. Мест под
  рисунки на постере восемь и они не меняются — меняется то, что в них нарисовано.

Не редактируется — это каркас формы:

- номера и названия плашек («1. Тема месяца», «Идеи на следующий месяц» и т. д.);
- набор тем (их ровно сто) и набор рисунков (двадцать) — из них только выбирают;
- то, какая краска за какую секцию отвечает и где на постере стоят рисунки;
- легенда настроений, вёрстка и порядок секций;
- цвет человека — он выводится из рисунка (папа — синий, мама — розовый, сын — зелёный,
  дочь — оранжевый);
- количество недель (всегда 4) и число дней месяца (считается из месяца).

## Месяц подставляется сам

Новый лист берёт месяц от сегодняшней даты: **до 10-го числа — текущий месяц, с 10-го —
следующий** (лист обычно печатают заранее). Число дней в календаре настроений считается
из месяца: 28, 29, 30 или 31. Вручную месяц переключается стрелками ‹ › в режиме правки —
дни пересчитываются сами.

## Адреса

Содержимого в адресе нет. В нём стоит короткий код строки — шесть знаков из алфавита
Кроуфорда, перестановка битов её id (сеть Фейстеля, `src/model/shortcode.ts`).
Пространство ровно 32⁶ = 2³⁰ ≈ 1,07 млрд, перестановка взаимно однозначна, поэтому
коллизий не бывает вовсе, а id не переиспользуются — код постоянен.

| Адрес | Кто откроет |
| --- | --- |
| `/season/<code>` | только владелец |
| `/s/<code>` | кто угодно: это витрина |
| `/p/<token>` | кто угодно, у кого есть ссылка |

Токен личной ссылки, в отличие от кода, **случайный** (16 знаков, 80 бит): его отзывают
и выдают заново, а перестановка битов всегда дала бы один и тот же ответ.

Единственное, что ещё едет в адресе, — оформление выложенного сезона: `?p=<тема>&i=<рисунки>`.
Это перебивка, а не содержимое: в строке лежит своё оформление, но примеривший чужой
постер в своей теме должен уметь прислать ссылку на то, что видит. Незнакомое значение
равносильно его отсутствию. Списки id — `tools/palettes/source.json` и
`tools/icons/source.json`.

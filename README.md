# Семейный сезон

Постер следующего месяца вашей семьи — что ждёт вас и близких: название сезона, четыре
недели с местом под фото, личные проекты каждого и хроника настроений.

Метафора зашита в название: месяц — это сезон, недели — серии, личные проекты — сюжетные
линии, итоги — финал, а идеи на следующий месяц — анонс. Замысел простой: соберите постер
заранее, распечатайте на двух листах A4, повесьте на холодильник и проживите месяц.

На `/` — лендинг с объяснением и тремя готовыми примерами: «Месяц Человека-паука» на четверых,
«Месяц настолок» на троих и «Месяц первых раз» на пятерых — сезоны нарочно разной
прожитости, от только начавшегося до законченного, и каждый в своей теме оформления
и со своими рисунками. Любой можно **форкнуть** и переписать
под свою семью, либо собрать сезон с нуля. Готовый сезон целиком помещается в ссылку:
отправили — и у близких открывается ровно тот же постер.

Страницы сайта:

| Адрес | Что |
| --- | --- |
| `/` | Лендинг: как собрать сезон и что на постере |
| `/sheet` | Постер-пример; `/sheet#data=<id>` — другой пример, `/sheet#d=…` — свой сезон |
| `/sheet/edit` | Тот же сезон в правке; без ссылки — пустой бланк |
| `/seasons` | «Мои сезоны»: свои сохранённые сезоны и избранное, только для вошедших |
| `/api/auth/*` | Вход через Google (Auth.js) |
| `/ideas` | «Идеи сообщества» — витрина чужих сезонов, пока пусто |
| `/account` | Кабинет: язык, состав семьи для новых постеров, выход |
| `/privacy` | Политика приватности — её адрес требует Google |

Next.js (App Router, бандлер Turbopack) + TypeScript, стили — CSS Modules; в браузер
по-прежнему не едет ни одной сторонней библиотеки — Auth.js работает только на сервере,
кнопки входа это `<form>` с серверным действием. Сам постер целиком клиентский: он живёт
в хэше и до сервера не доходит.

## Запуск

```bash
npm install
npm run dev       # http://localhost:3000
npm run build     # прод-сборка в .next/
npm run start     # прод-сервер на собранном
npm run lint
npm run typecheck
```

## Вход

Вход через Google на Auth.js. Хранилища у него нет: сессия лежит в зашифрованной куке,
на сервере о пользователе не остаётся ни строчки. «Мои сезоны» открываются только вошедшим.

Чтобы вход заработал локально, нужны три переменные — образец в `.env.example`,
значения кладутся в `.env.local` (он не попадает в git):

```bash
npx auth secret            # запишет AUTH_SECRET в .env.local
```

`AUTH_GOOGLE_ID` и `AUTH_GOOGLE_SECRET` берутся из OAuth-клиента в Google Cloud Console
(тип Web application). Разрешённые redirect URI:

```
http://localhost:3000/api/auth/callback/google
https://<домен>/api/auth/callback/google
```

Проверка, что серверная часть поднялась:

```bash
curl http://localhost:3000/api/auth/providers
# {"google":{"id":"google","name":"Google","type":"oidc",…}}
```

## Хранилище

В базе три таблицы: настройки аккаунта (сегодня это состав семьи для новых постеров),
избранное и свои сохранённые сезоны. В двух последних лежит **адрес постера** — та же
строка, что стоит в адресной строке браузера, — а не разобранный бланк. Сезон
по-прежнему живёт в ссылке; сервер эту ссылку запоминает, чтобы её не приходилось
держать в закладках. У каждого аккаунта не больше ста сезонов и ста закладок.

```bash
# строка подключения — в .env.local, см. .env.example
npm run db:migrate       # накатывает tools/db/schema.sql, идемпотентно
```

Локально проще всего поднять базу в докере:

```bash
docker run -d --name family-season-db \
  -e POSTGRES_PASSWORD=local -e POSTGRES_DB=family_season \
  -p 5432:5432 -v family-season-pgdata:/var/lib/postgresql \
  postgres:18-alpine

# DATABASE_URL=postgres://postgres:local@localhost:5432/family_season
```

Том монтируется в `/var/lib/postgresql`, а **не** в `/var/lib/postgresql/data`: с 18-й версии
образ хранит данные в подкаталоге с номером версии, и старый путь он отвергает с ошибкой.
Снести всё вместе с данными — `docker rm -f family-season-db && docker volume rm family-season-pgdata`.

В проде подойдёт любой PostgreSQL — например Neon или Vercel Postgres. **Без базы сайт
работает**: лендинг, примеры, постер, печать и вход от неё не зависят. В кабинете при
этом на месте состава семьи и списка сезонов пусто, а внизу — тост «не удалось
загрузить»: показывать вместо настоящих данных умолчание значило бы врать. Ни имени,
ни почты в базе нет — строки именуются непрозрачным ключом аккаунта.

Проверить, как выглядит отвалившаяся база, проще всего так — остановить контейнер и
открыть `/account`:

```bash
docker stop family-season-db     # в кабинете пусто и тост, остальной сайт работает
docker start family-season-db
```

В логах сервера при этом будет строка `[db] запрос не прошёл (settings:read:account,
код ECONNREFUSED)` с кодом Postgres и причиной — наружу она не выходит намеренно.

## Деплой

Vercel определяет Next.js сам: подключить репозиторий, собрать без дополнительных настроек.
Переменные `AUTH_*` и `DATABASE_URL` заводятся в настройках проекта; `AUTH_URL` не нужен —
адрес Vercel подставляет сам. Переменные подхватываются новым билдом: заведёте после
деплоя — нужно пересобрать.

**Схему на прод накатывают руками — сама она не появится.** Ни один шаг сборки миграцию
не зовёт (её падение завалило бы деплой сайта, который работает и без базы):

```bash
vercel env pull --environment=production .env.production.local
node --env-file=.env.production.local tools/db/migrate.mjs
```

Зовём скрипт напрямую, а не `npm run db:migrate`: тот подмешивает `.env.local`, и накатить
на дев вместо прода слишком легко. Перед подключением скрипт печатает хост и имя базы —
это и есть проверка, что едем куда надо.

В `next.config.ts` не стоит включать `output: 'export'`: статический экспорт выключает
роут-хендлеры, а серверная часть в планах.

## Два слоя: бланк и заполнение

| | Шаблон (бланк) | Заполнение |
| --- | --- | --- |
| Что это | Всё, что печатается: заголовки, тема месяца, недели, состав семьи, проекты и цели | Настроения по дням, прогресс проектов, записи в «Итогах месяца» и «Идеях на следующий месяц», фото |
| Где живёт | Только в ссылке (`#d=…`) | В локальном JSON (`src/data/examples/<id>.json`) |
| Едет в ссылку | да | нет |
| Печатается | да | нет |

Печать всегда даёт **пустой бланк**: шкалы прогресса пустые, клетки настроений пустые, поля для записи
(«Итоги месяца», «Идеи на следующий месяц») пустые, в полароид-рамке пустое место под вклейку бумажного фото. Заполняется всё руками
уже на бумаге. Заполнение существует только для примеров — чтобы показать, как выглядит
прожитый месяц. Какой набор показать, говорит пометка `data=<id>` в ссылке примера, так что
примеров со временем может стать больше одного.

## Печать: ровно две страницы A4

Лист рассчитан на две страницы, по две нумерованные секции на каждой:

| Страница | Что на ней |
| --- | --- |
| 1 | Шапка, «1. Тема месяца», «2. Недели месяца», «Наша цель на месяц» |
| 2 | «3. Личные проекты», «4. Настроение нашей семьи», «Идеи на следующий месяц» |

Свободное место на каждой странице уходит внутрь одного блока — поля для записи от руки:
на первой это рамка «Итоги месяца» внутри темы месяца, на второй — «Идеи на следующий
месяц». Остальные блоки сохраняют веб-пропорции. Раскладка проверена на худшем случае — пять человек и месяц из
31 дня — и всё равно укладывается в два листа. В диалоге печати оставьте поля по умолчанию: разметка
рассчитана на поля 10 мм (`@page` в `src/styles/print.css`).

## Как пользоваться

1. Чистый постер — **Новый сезон** в шапке сайта (или **Собрать свой сезон** на главной):
   открывается пустой сезон сразу в режиме правки.
2. Из примера — **Посмотреть пример** (это `/sheet`), затем **Форкнуть пример**: адрес
   становится `/sheet/edit#d=…`. Обе кнопки — обычные ссылки: с Cmd/Ctrl или Shift
   постер откроется в новой вкладке или окне.
3. Править текст прямо на постере: клик по любому подчёркнутому месту.
   Кнопки темы и рисунков плавают в правом нижнем углу и работают всегда — и в
   правке, и в просмотре, и на примере: постер перекрашивается целиком, тема за
   темой, а рисунки меняются набор за набором.
4. **Скопировать ссылку** (иконка со звеном цепи) — отправить родным. У них откроется
   тот же постер в режиме просмотра; ссылкой на пример тоже можно поделиться, и он придёт вместе с заполнением.
   Месяц в такой ссылке замирает на моменте копирования: короткая ссылка лендинга
   (`#data=<id>`) считает его от «сегодня», а скопированная везёт готовый бланк.
5. **Сохранить** — положить сезон к себе в «Мои сезоны» под именем вида
   «Сентябрь 2026, Месяц Человека-паука». Кнопка всегда переспрашивает и даёт поправить
   имя; в правке у уже сохранённого сезона к этому добавляется выбор — переписать его
   или сохранить рядом ещё один, — и на этом правка заканчивается. **Готово** просто
   закрывает правку, ничего не записав. В просмотре кнопка погашена, пока то, что на
   экране, уже лежит в кабинете: это и есть признак «сохранено». Поправили что-нибудь —
   она снова доступна. Дважды один и тот же постер не сохранится: сайт узнаёт его по
   адресу, даже если вы открыли сезон обычной ссылкой.
6. **Звёздочка** в левом углу панели — отложить постер, который сейчас на экране: свой,
   чужой или пример. Избранное — это закладка, а не копия: в кабинет уезжает адрес
   постера как есть, вместе с месяцем, темой и заполнением примера. Залитая звезда
   значит «уже отложен», повторное нажатие убирает.
7. **Иконки в правом углу** — звено цепи копирует ссылку на сезон (внизу появляется
   уведомление), принтер печатает чистый постер (в диалоге печати выбрать
   «Сохранить в PDF»).
8. Повесить распечатку на холодильник и прожить сезон, отмечая всё от руки.

И «Сохранить», и «В избранное» требуют входа: если вы не вошли, постер предложит это
сделать и вернёт вас ровно туда, где вы были, — вместе с несохранённым сезоном.
В «Моих сезонах» оба списка ищутся по названию и сортируются по дате или по имени.

Правки автоматически пишутся в адресную строку — ссылка и есть единственный вид, в
котором существует лист. В браузере ничего не сохраняется, поэтому сохраните ссылку
(в закладки или отправьте себе), прежде чем закрывать вкладку, — либо нажмите
«Сохранить» и войдите: тогда ссылку запомнит сайт, и сезон найдётся в «Моих сезонах».

Режим виден в адресе: `/sheet#d=…` — просмотр, `/sheet/edit#d=…` — правка. Адрес правки
можно сохранить в закладки или открыть в новой вкладке — сезон откроется сразу готовым
к правке. Старые ссылки вида `/#d=…` (когда лист жил на главной) продолжают работать: они
сами уводят на `/sheet#d=…`.

Кнопки «назад» и «вперёд» работают как на обычном сайте: форк примера — это переход,
и включение правки тоже. «Назад» из правки возвращает к просмотру со всеми внесёнными
изменениями, ещё раз «назад» — к примеру, «вперёд» — обратно к сезону в том виде, в каком
его оставили. Правка текста новых записей в истории не создаёт, только обновляет ссылку.
Кнопка **Отмена** в правке — тот же шаг назад: к примеру, если пришли форком, к главной,
если начинали новый сезон. Сезон после неё не теряется — «вперёд» возвращает его целиком.
После «Готово» её нет: сезон живёт сам по себе, и отменять уже нечего.

## Что редактируется, а что нет

Редактируется (и попадает в ссылку):

- заголовок листа и лента-девиз;
- месяц (стрелки ‹ ›), подзаголовок темы, вопрос в блоке «Итоги месяца»;
- подписи-заметки секций, названия и тексты четырёх недель;
- общая цель месяца;
- состав семьи: от 2 до 5 человек — имя, рисунок (папа / мама / сын / дочь, меняется кликом
  по аватару), название проекта, описание, личная цель;
- тема оформления — **сто наборов** из подборки Canva «100 цветовых сочетаний»
  («Пустыня», «Морская волна», «Кухня 1950-х»…). Плавающая кнопка в правом нижнем углу
  бросает постер в случайную другую тему, а название текущей видно прямо на ней. Выбранная тема
  уезжает в ссылку вместе с сезоном (отдельной пометкой `p=`, её видно и можно поправить
  руками) и печатается. Тему задают четыре краски набора — ими красятся плашки, рамки,
  чернила и герои, никаких других цветов на постере нет. Тема красит только постер: сайт
  вокруг него нейтрально-графитовый и не меняется никогда;
- рисунки постера — **двадцать наборов** по восемь рисунков («Классика», «Зима»,
  «Путешествие», «Питомцы»…). Вторая плавающая кнопка бросает постер в случайный
  другой набор, а три рисунка текущего видно прямо на ней. Набор устроен как тема:
  уезжает в ссылку отдельной пометкой `i=`, переживает форк и печатается. Мест под
  рисунки на постере восемь и они не меняются — меняется то, что в них нарисовано.

Не редактируется — это каркас формы:

- номера и названия плашек («1. Тема месяца», «Идеи на следующий месяц» и т. д.);
- набор тем (их ровно сто) и набор рисунков (двадцать) — из них только выбирают;
- то, какая краска за какую секцию отвечает и где на постере стоят рисунки;
- легенда настроений, вёрстка и порядок секций;
- цвет человека — он выводится из рисунка (папа — синий, мама — розовый, сын — зелёный,
  дочь — оранжевый);
- количество недель (всегда 4) и число дней месяца (считается из месяца).

## Месяц подставляется сам

Новый лист берёт месяц от сегодняшней даты: **до 10-го числа — текущий месяц, с 10-го —
следующий** (лист обычно печатают заранее). Число дней в календаре настроений считается
из месяца: 28, 29, 30 или 31. Вручную месяц переключается стрелками ‹ › в режиме правки —
дни пересчитываются сами.

## Ссылка

Шаблон пакуется в компактный массив, сжимается `CompressionStream('deflate-raw')`
и кодируется в base64url — целиком в хэше, на сервер ничего не уходит. Заполненный
пример укладывается примерно в 990 символов URL, пустой лист — в 250. Если браузер
не умеет `CompressionStream`, используется несжатый запасной формат; битая ссылка
не ломает страницу — откроется демо.

Тема оформления едет рядом с блобом отдельным словом — `#d=…&p=greece`. Её видно
в адресе и можно поменять прямо там: подставьте id любой из ста тем (список —
`tools/palettes/source.json`), и лист перекрасится без перезагрузки. Незнакомое
значение равносильно его отсутствию — тогда тема по умолчанию, «Янтарь и лазурь».

Набор рисунков едет там же и так же — `#d=…&p=greece&i=winter`; список id —
`tools/icons/source.json`. Незнакомое или пропущенное значение равносильно набору
по умолчанию, «Классике», поэтому ссылки, отправленные до появления наборов,
открываются с теми же рисунками, что и раньше.

Ссылки прежних версий (`3z`/`3p`, `1z`/`1p`) открываются по-прежнему. У формата 1
темы не было вовсе, а у формата 3 она ехала внутри блоба и теперь не читается,
поэтому обе разновидности показываются темой по умолчанию, если в адрес не дописать `p=`.
